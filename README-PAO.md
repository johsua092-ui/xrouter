# ใช้งาน X Router บน Windows

เปิด [ศูนย์ควบคุม](http://127.0.0.1:20128/dashboard) แล้วใช้รหัสผ่านผู้ดูแลที่ตั้งไว้ เปิดจาก Desktop ได้ด้วยทางลัด **X Router Control** ซึ่งมีเมนูเปิด Dashboard, เริ่ม, หยุด, รีสตาร์ต และสำรองข้อมูลใน system tray การปิดไอคอน tray จะไม่ปิดเซิร์ฟเวอร์ ตัวควบคุมไม่ได้ลงทะเบียนให้เปิดอัตโนมัติหลังบูต Windows

ถ้าใช้ PowerShell ให้เปิดในโฟลเดอร์โปรเจกต์:

```powershell
pwsh -NoProfile -File scripts/windows/XRouter-Control.ps1 -Action Status
pwsh -NoProfile -File scripts/windows/XRouter-Control.ps1 -Action Restart
```

ตั้ง Base URL ของโปรแกรมที่เชื่อมเป็น `http://127.0.0.1:20128/v1` และใช้ API Key ของ **X Router** ที่สร้างจากหน้า **API และคีย์** โปรไฟล์โมเดลที่ตั้งไว้:

| ชื่อที่ใช้เรียก | ใช้กับ | เส้นทางเริ่มต้น |
|---|---|---|
| `pao-code` | เขียนโค้ด | Gemini Flash ผ่าน CrowLLM |
| `pao-chat` | ถามทั่วไป | Gemini Flash ผ่าน CrowLLM |
| `pao-economy` | คำตอบสั้น | Gemini Flash ผ่าน CrowLLM |

ดูและแก้เส้นทางที่ใช้อยู่จริงได้ที่ [หน้าโปรไฟล์โมเดล](http://127.0.0.1:20128/dashboard/combos) ทั้งสามโปรไฟล์ใช้ CrowLLM ส่วนบัญชี Grok ถูกนำออกจาก X Router แล้ว ถ้าต้องการเรียกโมเดลโดยตรง ให้ใช้ `crowllm/gemini-3-flash:free`

Hermes ใช้ `pao-economy` เป็นค่าเริ่มต้น และเลือก `pao-code` ได้สำหรับงานที่ต้องเรียกเครื่องมือ ถ้าผู้ให้บริการส่งข้อผิดพลาดก่อนเริ่มตอบ X Router จะใช้คีย์ถัดไปตามกฎการลองซ้ำ หากเริ่มส่งคำตอบหรือคำสั่งเครื่องมือแล้ว ระบบจะส่งข้อผิดพลาดให้แอปแทนการเริ่มตอบใหม่ เพื่อไม่ให้ข้อความหรือคำสั่งเครื่องมือซ้ำ

ในหน้า [ศูนย์ควบคุม](http://127.0.0.1:20128/dashboard) สถานะ **ส่งข้อความสำเร็จแล้ว** อิงจากบันทึกการสร้างคำตอบ ส่วน **ผ่านตรวจสิทธิ์** หมายถึงยังไม่ได้ยืนยันว่าคีย์นั้นสร้างคำตอบได้ หากขึ้น **ต้องเชื่อมใหม่** ให้ไปที่ผู้ให้บริการนั้นและเชื่อม OAuth ใหม่ การทดสอบจะไม่ลบบัญชีที่ refresh token ถูกปฏิเสธโดยอัตโนมัติ

ในเมนู **สำรองและตรวจการกู้คืน** สามารถสร้างสำเนาฐานข้อมูลแบบเข้ารหัสและเปิดตรวจสำเนาได้ทันที แอปจะตรวจว่าถึงเวลาสำรองรายวันขณะที่เปิดอยู่ การตรวจสำเนาจะถอดรหัสและเปิดฐานข้อมูลในพื้นที่ชั่วคราว โดยไม่เขียนทับฐานข้อมูลที่กำลังใช้งาน สำเนาเก็บใน `data/backups-encrypted` และใช้กุญแจใน `data/security/vault-key.dpapi` ภายใต้บัญชี Windows เดิม การย้ายไปเครื่องหรือบัญชี Windows อื่นต้องเตรียมย้าย credentials แยกต่างหาก ส่วนไฟล์นำเข้าและสำเนาก่อนอัปเกรดไม่ได้ถูกเข้ารหัสย้อนหลัง

บันทึกผลอัปเกรดอยู่ใน `data/upgrade-production-checks.json` และ `data/upgrade-windows-control.json` ส่วน `data/upgrade-session.json` ระบุตำแหน่งสำเนาก่อนสลับรุ่น เก็บไฟล์เหล่านี้ในเครื่อง เนื่องจากสำเนาฐานข้อมูลก่อนอัปเกรดอาจมี credentials แบบเดิมอยู่

รอบบำรุงรักษาวันที่ 6 พฤศจิกายน 2569 แก้การค้นหาโมเดลรายตัวที่ตอบ 500 และให้เส้นทางนี้ตรวจคีย์ตามการตั้งค่าเดียวกับรายการโมเดล อัปเดต Geist เป็น 1.9.2 และแก้พาธกับการปิดฐานข้อมูลในชุดทดสอบ Windows รุ่นที่เปิดใช้อยู่คือ `.next-maintenance-20261106` โดยเก็บ `.next-full-upgrade` สำหรับย้อนกลับ ผลตรวจและตำแหน่งสำเนาก่อนเปลี่ยนอยู่ใน `data/maintenance-20261106/report.json` ชุดทดสอบเฉพาะส่วนผ่าน 46 เคส การตรวจรุ่นบนข้อมูลจำลองผ่าน 12 กรณี และการตรวจระบบจริงแบบอ่านอย่างเดียวผ่าน 7 กรณี แต่ชุดทดสอบทั้งโปรเจกต์ยังมีข้อผิดพลาดเดิม 314 เคส และ lint ยังมี 176 errors จึงยังไม่ถือว่าทั้งโปรเจกต์ผ่านการตรวจครบถ้วน

รอบบำรุงรักษาวันที่ 8 พฤศจิกายน 2569 อัปเกรดหน้าศูนย์ควบคุมให้ใช้ design system เต็มรูปแบบ: สถานะแสดงเป็นชิปสีตามโทนเรียงตามความรุนแรง ตารางบัญชีมีอวตารผู้ให้บริการและแถวไฮไลต์เมื่อชี้เมาส์ การโหลดครั้งแรกเป็นโครงร่างจองพื้นที่ และมีเวลาอัปเดตล่าสุดกำกับที่หัวหน้า โดยไม่เปลี่ยนการทำงานหรือสิทธิ์การเข้าถึงใดๆ ด้านการสร้างรุ่น สคริปต์ `copy-standalone-assets` อ่านค่า `NEXT_DIST_DIR` จากไฟล์ `.env` เองเมื่อสภาพแวดล้อมไม่ได้ตั้ง ทำให้ `npm run build` ตามด้วยการเปิดเครื่องผ่าน `XRouter-Control.ps1` ใช้ได้ทันทีโดยไม่ต้องสั่งสำเนาไฟล์เอง ส่วน dependencies อัปเดตเฉพาะระดับ patch/minor ภายในช่วง semver ที่ประกาศไว้ ชุดทดสอบทั้งโปรเจกต์หลังรอบนี้มีข้อผิดพลาด 315 เคส และ lint มี 177 errors ซึ่งเพิ่มขึ้นฝั่งละ 1 จาก deps ที่เลื่อนรุ่น ไม่ใช่จากโค้ดที่แก้ในรอบนี้ รอบนี้ยังรวมงานจากก่อนหน้าที่เคยค้าง ได้แก่ การเข้ารหัส credentials ด้วย AES-256-GCM ผูกกับ DPAPI ของ Windows การสำรองฐานข้อมูลแบบเข้ารหัสรายวัน และไฟล์ `README-PAO.md` นี้เอง ทั้งหมด rebased บน upstream `a1969d1` โดยไม่มีความขัดแย้ง เก็บสำเนา `.next` ก่อนอัปเกรดไว้ที่ `.next-backup-20261108` และเผยแพร่งานขึ้น fork สาธารณะ `paopaonyapi-creator/xrouter` กับ mirror ส่วนตัว `paopaonyapi-creator/xrouter-mirror` ให้ตรงกับเครื่องนี้ทุก commit ส่วน `origin` (`johsua092-ui/xrouter`) ยังรับ push จากเครื่องนี้ไม่ได้เพราะไม่มีบัญชีในเครื่องมีสิทธิ์เขียน
